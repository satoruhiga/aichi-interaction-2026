# Python から TouchDesigner へデータを渡す

送信するデータの意味を決め、JSON として受け取り、TD で使える表やチャンネルへ変換するための考え方。座標の表示への変換は [coordinates.md](coordinates.md) を参照する。

## 送るものは状態かイベントか

位置・温度・検出結果のような状態は、古い値より新しい値が重要になる。一方、ボタン操作や記録などのイベントは、途中の1件を省くと意味が変わる。まずどちらを扱うか決める。

次に、各メッセージが全状態を表すのか、前回からの差分なのかを決める。全状態なら受信結果で置き換えられる。差分なら適用順序や再接続時の初期状態も扱う必要がある。これらはアプリケーションの約束であり、WebSocket が決めるものではない。

JSON のフィールドには、受信側で意味を判断できる名前を付ける。数値の単位、座標系、時刻の基準は送信側の仕様として明記する。

## 配列の順番と識別番号を使い分ける

固定順序の全要素を毎回送るなら、添字を要素番号として使える。番号を各要素へ重複して入れる必要はない。

送信前に間引く、欠測要素を省く、順序を変える場合は、添字から元の番号を復元できない。対応関係を保つための ID を送る。フレームをまたいで同じ対象を追う場合も、検出配列の順番と固定 ID を区別する。

複数対象は、対象ごとに関連する値をまとめる。点群なら入れ子の配列が一例になるが、すべてのデータを点群の構造に揃える必要はない。受信後に平坦な表へ変換する場合は、必要な対象の区切りや ID を残す。

## WebSocket と JSON を TD で受け取る

WebSocket では一方が待ち受けるサーバー、他方が接続するクライアントになる。接続を開始する方向と、データを送る方向は別。TD の WebSocket DAT から接続する場合、相手側にサーバーを用意する。

```text
WebSocket DAT → Select DAT → JSON DAT → 必要なら DAT to CHOP
```

1. WebSocket DAT のアドレスとポートを送信側の待受設定に合わせる。
2. Select DAT で見出しを除いたメッセージ本文を取り出す。最新状態だけ使う場合は受信履歴を制限する。全イベントを処理する用途では、最新行だけ読む方法にしない。
3. JSON DAT で必要な部分を選ぶ。表として使う場合は Output を Filter Results、Output Format を Table にする。

JSON DAT に任せる場合、コールバックで JSON をパースして再整形する処理を重ねる必要はない。受信時に独自の処理を実行したい場合はコールバックを選ぶ。

## JSONPath で選び、表の向きを決める

例えば次のデータを受け取るとする。

```json
{"items": [{"x": 0.2, "y": 0.7}, {"x": 0.8, "y": 0.3}]}
```

| 取り出すもの | JSONPath |
|---|---|
| 最初の要素 | `$.items[0]` |
| 全要素をそれぞれ取り出す | `$.items[*]` |
| 配列全体を1つの結果として取り出す | `$.items` |

辞書のリストを表にすれば、要素ごとの行とフィールドごとの列として扱える。上の例で Table Column Headers を `x y` にすると、座標の2列になる。

CHOP へ渡す場合は、何をチャンネル、何をサンプルにするかを決める。例えば x・y を行に転置し、DAT to CHOP で各行をチャンネルとして読む。転置は必須ではなく、DAT to CHOP 側の読み方と組み合わせて決める。

複数サンプルを持つチャンネルを1つのパラメータから参照しても、対象数ぶんの処理が自動で作られるわけではない。対象サンプルを選ぶか、複数対象を扱う後段を用意する。

## 対象なしと通信断を分ける

対象がなくなった状態は、空配列や有効フラグなどで明示する。送信を止めるだけでは「変化がない」「対象がない」「通信が切れた」を区別できない。

空配列は有効な状態更新、通信断は更新が届かない状態。表示を消す用途では、空データに加えて切断通知や更新タイムアウトも扱う。JSON DAT の Hold Last Non-Empty Results や後段の保持設定が、意図と一致するか確認する。

## この workspace の共通送信部

[common/json_sender.py](../common/json_sender.py) は、TD の WebSocket サーバー（Web Server DAT）へ接続して最新状態を送るクライアント。イベントを全件届ける送信部ではない。

```python
from common.json_sender import JsonSender

with JsonSender() as sender:
    for state in state_stream:  # アプリ側で用意する継続的な状態の供給元
        sender.publish(state)
```

- 既定の接続先は `ws://127.0.0.1:8765`。TD が同じ PC で待ち受ける。切断時は自動で再接続する。
- publish する値は `type` を持つ辞書。値は JSON 化できる辞書・リスト・数値など。NumPy 配列は `.tolist()`、スカラーは `.item()` などで変換する。NaN・Infinity は受け付けない。
- 送信待ちは `type` ごとに最新1件だけ保持し、約30Hzで新しい値を送る。中間の publish 結果は省略され得るため、各値は単独で解釈できる全状態にする。
- `publish()` は送信完了を待たない。処理ループを with の中で継続し、呼び出し直後に終了しない。
- 通信バッファや受信処理にも遅延があるため、約30Hzは到達速度や遅延の保証ではない。
- TD から送られたメッセージは毎回読み出す。`JsonSender(on_message=関数)` を渡すと JSON の辞書を受け取れる。渡さなければ捨てる。TD 側は接続中の全クライアントへ送ってよく、各プロセスは自分が扱う `type` だけに反応する。

教材ごとのデータ形式と起動方法は、その教材の README に記載する。
