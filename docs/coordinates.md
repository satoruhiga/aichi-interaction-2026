# TouchDesigner で画像座標を表示位置に変換する

画像解析の位置を使って点や画像を配置するときのノウハウ。目・手・姿勢など、対象が変わっても同じ手順で考える。教材固有の送信仕様は各日の README とコードで確認する。

## 最初に座標の意味を揃える

「0〜1の座標」だけでは変換は決まらない。入力と表示先について、原点（左上・左下・中央）、軸の方向、単位（割合・ピクセル・3Dの距離）、基準画像を確認する。リサイズ・クロップ・余白・鏡像も確認する。

以下では左下原点、画像全体を0〜1に正規化した座標を `(u, v)` とする。左上原点なら `v = 1 - y` で揃える。反転済みの値には重ねて適用しない。

映像自体の反転と解析後の座標変換は別の処理。まず解析に渡る画像の向きを確定し、その画像に対する座標を表示先へ変換する。

同じ入力を2D・3Dに使うなら、用途固有の変換は分岐した表示側に置く。共通の送信値を片方の表示に合わせて変更しない。

## TOP で画像を指定位置に置く

次の条件なら、中心からの移動量は `tx = u - 0.5`、`ty = v - 0.5` になる。

- Translate Unit は Fraction（F）。
- 素材を配置するキャンバスと合成先の寸法・縦横比が揃っている。
- Pivot は中心、変換順序は Scale → Rotate → Translate。後段に追加の位置変換がない。

Math CHOP の From Range を0〜1、To Range を−0.5〜+0.5にしても同じ変換になる。両軸とも各軸の全体に対する割合なので、3D用の縦横比補正を加えない。

Translate Unit の P（Pixels）・F（Fraction）・A（Fraction Aspect）を混同しない。上の式は F 用。パラメータ名と単位は実機で確認する。

位置がずれるときは、補正を足す前に原因を確認する。

- 素材と背景の解像度が違う：同じキャンバスへ配置するか、基準寸法の違いを換算する。
- 見た目の中心が合わない：透明余白、アンカー、Pivot を確認する。
- 縮小すると位置も動く：変換順序と Pivot を確認する。
- 画像が端で繰り返される：Extend を確認する。切り落とす用途では Zero を検討する。
- 背景が隠れる・縁が不自然：アルファ、プリマルチプライ、合成順を確認する。加算と Over は同じではない。

単に画像を重ねたいなら TOP だけで成立する構成から考える。3Dの遮蔽や回転が必要なら Geometry・Material・Camera を使う構成を検討する。

## 平行投影の3D空間に配置する

次の条件なら `X = u`、`Y = v * image_height / image_width` で画像の横幅を1とする3D座標へ変換できる。

- Camera は Orthographic、Ortho Origin は Bottom Left、Ortho Width は1。
- カメラは正面向きで XY 移動がなく、Window 等の追加変換もない。
- 正方形ピクセルで、解析画像と Render の縦横比が等しい。クロップや余白がない。

16:9なら Y に9/16を掛ける。これは上下反転ではなく、縦横の距離の尺度を揃える操作。SOP・POP・CHOPなど表示に渡す途中で一度だけ行う。

中心原点、別の Ortho Width、追加のカメラ変換では式をそのまま使わず、カメラが映す範囲に対応づける。異なる縦横比への Fit/Crop がある場合は、その表示変換も位置に適用する。

平面への配置なら Z=0 を使える。奥行きを使う場合は、Z の意味・単位・符号・尺度を送信元の仕様で確認する。相対的な奥行きか実距離かは解析器によって異なる。表示時の遮蔽も別途確認する。

## 症状から確認箇所を絞る

| 症状 | 最初に確認すること |
|---|---|
| 上下・左右が逆 | 原点、軸の方向、鏡像、二重反転 |
| 中央では合うが端でずれる | 範囲、単位、縦横比、Fit/Crop、余白 |
| 全体が同じ量だけずれる | 中心と左下の違い、Pivot、透明余白 |

中央だけでなく左右・上下で確認する。データが届くこと、位置が合うこと、遅延が許容できることは別々に検証する。

対象数や空データの扱いは [データ受け渡しのノウハウ](python-to-touchdesigner.md) を参照する。
